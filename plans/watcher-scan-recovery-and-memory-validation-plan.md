## 1. Outcome and evidence boundary

Make Codex discovery, stat, and parse failures consistently retryable and visible; avoid repeatedly parsing unchanged healthy files while a failure holds the scan watermark; replace the weak large-input probe with tests that prove which input was consumed; and measure the supported workload before accepting a resource budget.

The historical duplicate incident remains explained by accepted exports followed by failed local checkpoints and watcher restarts. Advisory locking and delivery diagnostics are already deployed. This follow-up does not reopen that RCA or promise exactly-once delivery.

The prior streaming change remains useful. It removes whole-file string/split copies and filters processed turns before retaining observations. It does **not** establish constant memory: `ReadBytes('\n')` and JSON decoding allocate for an entire record, and all selected turns and tool associations remain in memory until parsing finishes.

The 60-minute service observation and automatic Codex canary are valid historical observations. They do not supply a workload-derived host capacity budget. The later substitution of a 4 GiB `MemAvailable` threshold for the original memory/swap recovery condition was not justified before testing. Do not treat that substitution as a passed gate.

### Findings to preserve

| Finding | Evidence at the starting source | Required correction |
| --- | --- | --- |
| Stat errors can lose eligibility | `ScanOnce` continues after `os.Stat` errors without setting `scanFailed`; a later watermark can exceed a restored file's unchanged mtime | Hold progress on any uncertain stat result and test recovery at the old mtime |
| Discovery hides failures and can omit nested files | `SessionPaths` ignores walk errors and uses a one-directory glob before recursive fallback; a shallow match suppresses deeper discovery | One recursive discovery implementation returning partial paths plus errors |
| Parse failure causes repeated work | Corrupt input pins the global watermark; every eligible healthy source is parsed again every poll | Preserve conservative progress, with a disposable cache of successful unchanged scans |

| Probe counts and memory claims are overstated | `processed_traces` is the size of the entire loaded state; RSS is externally observed, with no budget assertion | Report actual source/state overlap and measure isolated workers against criteria fixed first |
| Existing functional filter tests cannot prove retention behavior | Their final output would also pass if all turns were parsed and filtered later | Add a mechanism assertion and independent resource measurements |

The preceding audit reproduced the stat, corrupt-input, and vacuous-probe cases with temporary synthetic sources. Those examples are diagnostic evidence, not registered regression tests. W1 must turn them into executable regressions.

## 2. Fixed design decisions

1. Keep state version 3, its single state file, persistent advisory sidecar, and read/mutate/atomic-write transaction. No schema migration is needed.
2. Keep at-least-once sending and existing per-turn checkpoints. Never mark a trace processed before successful span/score work. Retry a pending score without resending spans.
3. Keep one global discovery watermark. Any discovery, stat, parse, or ordinary per-turn delivery failure prevents its advancement for that scan. Successful turns may still commit individually. Continue healthy work after a recoverable source failure.
4. Use process-local metadata only to suppress redundant parsing. It is an optimization, never a second progress store. Restart, cache eviction, or cache invalidation may cause rereading; none may cause a turn to be marked processed or skipped permanently.
5. Keep `ScanOnce` as a one-shot entry point. Add a private scan function and private runtime object shared across `WatchSessions` iterations. Unit tests in package `watch` can exercise that private interface. Do not introduce public CLI flags for test injection.
6. Report incomplete scans as failures in diagnostics even with `Quiet=true`, without returning an ordinary source error from the watch loop and causing a restart. State I/O/checkpoint errors and cancellation retain their existing fatal/cancellation behavior.
7. Do not repurpose the Claude hook queue as a Codex discovery retry ledger. Its current parser is unfiltered, and successful empty/non-exportable transcripts do not drain it. Changing that contract is unnecessary here.
8. Do not cap, truncate, discard, or mark large input processed to meet memory targets. Do not flush a turn merely because the next `turn_context` appeared: the parser supports revisited turn IDs and tool associations.
9. Preserve the existing fixture inventory and normalized projection. New checked-in source/golden fixtures belong in `testdata/manifest.json`. Large synthetic inputs are generated privately at test time, not committed as another fixture corpus.
10. Keep Claude hooks, pricing, gateway/reconciliation, export transport, manual export scope, and receiver deduplication outside this change. Shared state/hook regression tests remain required.

### Deliberate limits of the selected recovery design

This remains an mtime-based scanner of currently discoverable sources, not a durable archive of every previously seen pathname. A discoverable source whose stat/read fails must remain eligible when access recovers. A failed discovery must not certify a complete scan. A corrupt eligible source remains degraded until it is repaired or deliberately removed from the watched source tree by its owner.

A file deleted from discovery and later restored with an mtime older than an already successful watermark is outside the existing automatic discovery guarantee. So are arbitrary rewrites that preserve file identity, size, and mtime. This plan must not claim to repair those cases, and the cache must not broaden that limitation. Supporting them would require a separate discovery/reconciliation contract. Do not hide this limit behind an in-memory list that disappears at restart.

A missing `sessions/` directory is conservatively an incomplete Codex discovery, including on a fresh host. Keep the old watermark and continue draining the existing hook queue. Doctor may report degraded Codex discovery on a host where Codex has not created its directory; explain the cause instead of resetting progress or inventing an exclusion flag.

### Why this design

| Alternative | Decision |
| --- | --- |
| Advance the watermark after a warning | Reject: loses retry eligibility |
| Pin the watermark and reparse everything forever | Correct conservative progress, but unnecessary repeated allocation/CPU; add the disposable cache |
| Persist failed paths and advance a global watermark | Defer: requires a versioned durable retry contract, removal semantics, and compatibility with all state writers/rollback |
| Use the existing hook queue for every Codex failure | Reject for this scope: changes queue completion, filtering, and eligibility semantics |
| Drop corrupt/oversized input after N tries | Reject: silent data loss |
| Rewrite the whole parser into a turn iterator now | Defer unless measured budgets fail; interleaved contexts and call matching require a separate semantic design |

### W3 — Avoid redundant work without changing durable state

1. Introduce a private `scanRuntime` shared by `WatchSessions`; `ScanOnce` creates a fresh instance for one call. A new watcher process starts empty. Test seams and fake clock belong to this private layer.
2. Store at most 1,024 per-path metadata entries, with LRU eviction. This is a cache capacity, not a limit on sources scanned/exported. Eviction causes normal work on the next eligible scan. Store no turns, observations, input/output text or decoded JSON in entries.
3. A successful entry requires a successful parse, no failed actionable turn, and successful post-parse stat with the same file identity (`os.SameFile`), size and nanosecond mtime as before parsing. If the source changed or post-stat failed, do not cache success and do not advance the watermark past uncertain work. Already committed turns remain committed.
4. On each scan, still discover and stat sources. Bypass parsing only when an eligible source's successful fingerprint is unchanged. Cache entries are never used to bypass discovery/stat errors or the ordinary mtime interval. Successful empty, processed-only or currently incomplete sources may be cached after stable parsing; later appends must invalidate the fingerprint.
5. Do not cache success when any selected trace still needs a score/checkpoint. A score retry must use its persisted environment and send zero spans. After a successful retry, update the processed-ID membership set before handling subsequent sources in that scan.
6. Track failed parse attempts separately in the same bounded metadata cache. For an unchanged fingerprint, retry no more often than 30 seconds; changed identity/size/mtime retries immediately at the next poll. For stat/discovery errors retry normal discovery/stat each poll because no trustworthy fingerprint exists. No added background goroutines or CLI policy knobs.
7. A deferred parse retry is still an incomplete scan, pins the watermark and contributes to `parse_errors`. Healthy/new sources run every poll. The retry is due at the first poll on/after its deadline; do not sleep 30 seconds inside a scan.
8. Evicting a failure entry must cause another real attempt, not mark it recovered. A complete successful discovery that no longer contains a removed path may cease reporting it; document the source-removal/old-mtime restoration limit in section 2. Never mutate/delete a user's source to clear health.
9. Check context cancellation between sources and before waits. Preserve existing state-lock retry logic; this cache does not retry network sends or create a second checkpoint mechanism.

**Exit:** repeated scans parse an unchanged healthy source once while corruption remains; changed/new sources still progress; repair unblocks progress; restart and eviction cause safe rereads; pending scores are not suppressed. All tests use fake scan time and counters, not sleeps or scheduler-sensitive timing assertions.
